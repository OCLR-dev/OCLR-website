# Pick’em 玩家页设计（#1268）

[#1268](https://github.com/OCLR-dev/OCLR-website/issues/1268) 的交付物：`/tournaments/[edition]/pickem` 的低保真版面、场次卡完整状态、互动与无障碍规格，以及三语文案。上位设计见 [#1266](https://github.com/OCLR-dev/OCLR-website/issues/1266)，资料字段按 [#1270](https://github.com/OCLR-dev/OCLR-website/issues/1270) 建议的玩家 API 契约设计，结算与排行榜读模型来自 [#1271](https://github.com/OCLR-dev/OCLR-website/issues/1271)。

规则与中文文案仍是提案，需主办确认。所有队伍、玩家、时间与数字均为合成示例，不能作为赛季数据使用。

## 文件

- [wireframe.html](wireframe.html)：直接用浏览器打开。顶栏可切换语言、明暗和“模拟保存失败”；也可用 `?lang=en&theme=dark` 打开指定组合。第一张场次卡、玩法按钮、手机赛事菜单、排行榜范围切换、“定位到我”和显示开关都可以操作。
- [copy.md](copy.md)：146 条新文案的三语对照，由 [copy.mjs](copy.mjs) 从线框的 `COPY` 生成。改文案时只改 `COPY`，再执行 `node docs/design/pickem/copy.mjs`。
- [preview/](preview/)：线框截图，见文末列表。

## 页面结构

| 项目 | 设计 |
| --- | --- |
| 入口 | 公开赛事导航在“数据统计”之后加“赛事预测”。只有该届活动已启用并发布时才显示；停用时不显示入口，页面与 API 按 #1270 返回 404。 |
| 外壳 | 沿用 `TournamentShell` 的公开分支（`.event-context`、MainSheet 色票、明暗偏好 cookie、赛季外观）。导航在 52rem 以下收进“赛事菜单”，与现有公开页相同。 |
| 分页签 | “本轮场次 / 我的预测 / 排行榜”是链接，建议路由为 `/pickem`、`/pickem/mine`、`/pickem/leaderboard`。轮次、状态和榜单范围写进查询参数（`round`、`status`、`scope`），以支持深链接和浏览器返回。路由命名属提案。 |
| 桌面（容器 ≥ 900px） | 主区为场次清单，按“可预测 → 已截止 → 已结算与作废”分组；右侧 320px 侧栏依次为我的进度、本轮榜单前五名、玩法摘要，随页面滚动固定。 |
| 手机 | 单栏：标题与分页签 → 筛选（轮次、状态、已预测计数）→ 场次清单 → 我的进度 → 榜单摘要。完整榜单从分页签进入。 |
| 时间 | 一律用 `formatDate`（`src/lib/editions.ts`）：日期、24 小时制和赛季时区偏移，例如 `2026年11月28日 20:00 (UTC+8)`。倒数只作辅助，设为 `aria-hidden`，截止时间文字才是准确信息。 |
| 队徽 | 用 `TeamAvatar`，没有图片时显示队名前两个字的缩写。 |

## 场次卡

卡片由五部分组成：轮次与场次编号、状态标签；开赛与截止时间；提示（改期、更正、撤回）；选项或比例；底部说明与操作。状态同时用文字、图标和既有色票（accent、success、warning、danger、muted）表达。

选项是一组原生单选钮，放在带隐藏 `legend` 的 `fieldset` 里，没有默认选择。平局选项只在契约给出时出现：桌面位于两队之间，手机排在最后。长队名换行显示。每张卡只有一个“保存预测”按钮，在未选择或选择未改变时为 `aria-disabled`，但仍可聚焦。

下表的字母对应线框第 3 节的卡片。

| 状态 | 触发条件 | 显示 |
| --- | --- | --- |
| 可预测 · 未选（A） | `status=open`，没有本人选择 | 两队平行选项；提示先选择再保存 |
| 已选未保存（B）、改选未保存（E） | 本地选择与已保存选择不同 | 写明“尚未保存”；改选时同时写出目前保存的队伍 |
| 保存中（C） | `PUT .../pick` 进行中 | 选项暂时停用；按钮 `aria-busy` 并显示“正在保存…”；焦点留在按钮上 |
| 已保存（D） | `PUT` 成功 | 回执：所选队伍、保存时间、可修改时限；按钮变为“已保存” |
| 失败 · 网络或 5xx（F） | 请求失败 | 保留选择，用同一个按钮重试；错误以 `role="alert"` 读出 |
| 失败 · 版本冲突（G） | 409，`expectedVersion` 过期 | 写出服务器目前保存的选择；保留本地选择，以新版本重新保存 |
| 失败 · 登录失效（H） | 401 | 页首显示失效横幅和“重新登录”；未保存的选择按 edition、fixture、`windowId` 存进本标签页的 `sessionStorage`，登录回来后恢复为未保存 |
| 失败 · 已截止（I） | 409，截止 | 卡片转为已截止并揭晓比例，说明本次选择未保存 |
| 失败 · 已作废（AB） | 409，批次作废 | 卡片转为已作废，说明未保存与作废原因 |
| 截止确认中（J） | 本地时间已到 `closesAt`，服务器还未回传截止 | 停用选项，提示正在确认；前端不自行判定截止。服务器确认后转为已截止，并读出“此场次已截止。”（`live_closed`） |
| 已截止（K、L、M） | `status=closed` | 无记名比例条、百分比和票数；本人选择以文字标签标出；零票显示“尚无预测”；本人未预测时说明 |
| 待公布赛果（N、U） | 比赛已开始或结束，没有有效官方赛果；或赛果被撤回 | 显示“待计分”；撤回时说明原积分暂时移除 |
| 已结算（O、P、Q、S、T） | 有效的已发布赛果 | 赛果、胜方标签、得分（猜中 +1、未猜中 0、未预测）；改判时附说明；链接到赛果页 |
| 已作废（V、W、X） | 作废原因 | 原因与“不计分”，不显示比例。换队后重新开放会出现新卡片，原选择不带入 |
| 改期（Y、Z） | 开赛时间变化 | 延后：截止时间不变；提前：截止收紧，用警示色和图标提示 |
| 访客（AA） | 未登录，读 `GET /summary` | 只读：双方、开赛与截止，没有选项、比例或个人数据 |

比例由前端用 #1271 回传的票数计算，以最大余数法取整，使各项加总为 100%。比例条设为 `aria-hidden`，百分比和票数以文字呈现。

## 我的预测

表格列出场次、我的预测、赛果、得分和状态，可按轮次筛选。改判、撤回和作废写出当前状态，并链接到赛果页。表格上方显示全季积分、本轮积分和猜中数。手机把每行转为卡片，用 `data-label` 标出栏名。表格下方注明只有本人能看到这些预测。

## 排行榜

- 可切换本轮与全季；切到全季时隐藏轮次选单。表格上方注明已结算场次数。
- 同分同名次（1、2、2、4），名次下标“并列”，读屏读出“并列第 N 名”。并列可能跨页，应使用服务器回传的并列标记。
- 每猜中一场得 1 分，积分等于猜中数，所以“猜中”栏显示“猜中数 / 已结算的预测数”，用来区分跳过场次的玩家。
- 本人行高亮并加“你”标签。点“定位到我”时，若本人行已载入，就滚动到该行并把焦点移到该行；若本人不在当前页，底部固定显示“你的名次”与“定位到我”，点击后按 API 回传的本人名次和页码载入该位置，出现“回到榜首”，焦点移到本人行并读出名次。
- 显示开关以 `role="switch"` 放在榜单旁，说明会使用站内 osu! 公开名称并可随时关闭。切换时显示“正在更新…”；成功后立即加入或移除本人行；版本冲突时显示最新状态；失败时开关回到原状态并可重试。未加入榜单时，页面用横幅显示本人的本轮与全季积分。
- 只有至少一场预测已结算的玩家进入榜单。

## 访客

访客看到玩法、开放场次摘要和“使用 osu! 继续”。分页签“我的预测”和“排行榜”显示登录提示，不显示个人预测、比例或完整榜单。

现有 `/auth/osu` 登录完成后固定跳转到 `/dashboard`，只有桌面授权和转播返回例外。要做到“登录后回到同一赛季的预测页”，需要新增一个同站返回参数：只接受 `/tournaments/<slug>/pickem` 下的相对路径，并像 `streaming_return` 一样绑定 OAuth state。这一点需要在 #1270 或玩家页实作时补上。

## 页面级状态

线框第 7 节列出：载入中（骨架屏与 `aria-busy`）、没有可预测场次、筛选无结果、我的预测为空、排行榜尚无结算、载入失败、登录失效横幅、不符合参与资格（只读）、局部刷新后提示、显示设置的更新中、冲突和失败、访客打开“我的预测”或“排行榜”、玩法说明、手机赛事菜单。

## 键盘与辅助技术

- Tab 进入选项组，方向键切换队伍，再 Tab 到“保存预测”，按 Enter 或空格保存。
- 局部更新后焦点留在原来的控件上，不跳回页首。
- 每张卡有一个 `role="status"` 区域，读出“正在保存预测…”和“预测已保存：队名”；错误用 `role="alert"`。
- “玩法”打开原生 `dialog`（手机为底部面板），Esc 或关闭按钮收起，焦点回到打开它的按钮。手机赛事菜单按 Esc 收起，焦点回到菜单按钮。
- 触控目标至少 44px。开关动画遵循 `prefers-reduced-motion`。

## 请主办确认

1. [copy.md](copy.md) 的全部中文文案，以及上表的平局和登录失效用词。
2. 玩法第 2 条：截止不晚于开赛，比赛提前时截止随之提前，延后时截止不变。这是 #1266 和 #1267 的规则，线框把它写成给玩家看的说明。
3. 参与资格：线框为“仅限已接受报名者”准备了只读横幅；如果维持开放给所有登录帐号，就不显示这条横幅。
4. 分页签路由命名（`/pickem/mine`、`/pickem/leaderboard`）。

## 实作备注

- 文案以英文原文写在 `tr()` 中，用 `npm run i18n:extract` 生成词条，再执行 `npm run test:i18n`。占位符改为现有目录的 `{value0}` 写法。队名、轮次名与 osu! 名称保持原文。
- 线框里没有画出、但实作需要的文案变体：未并列名次 `rank_round`、未并列的本人名次条 `lb_self`、服务器确认截止时的播报 `live_closed`。
- 登录回应使用 `private, no-store`，以免快取混入其他帐号的选择（#1270）。首版不进入 Developer `/api/v1`。
- 验收的第二项（合成资料走完整流程，含手机、暗色、键盘和送出失败）在玩家 API 完成后进行，不属于本设计交付。

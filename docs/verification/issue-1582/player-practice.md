# #1582 選手技術分析與練習譜面

第二階段沿用[第一階段的圖池快照與 pgvector 查詢](README.md)。輸入公開 osu! UID，可取得 S9、S10 的實戰樣本數、相對強項、可加強的譜面需求、推薦理由，以及個人頁、對局和圖池來源。命令用本機 PostgreSQL 上的 pgvector 排出練習候選。

## 執行與重跑

使用第一階段的 `BEATMAP_SIMILARITY_DATABASE_URL` 設定。此例的 UID 在兩屆都有公開出賽紀錄。

```sh
npm run --silent beatmap:similarity -- player --osu-id 10260284 --validate
npm run --silent beatmap:similarity -- practice-snapshot > s9-s10-practice.json
npm run --silent beatmap:similarity -- player --osu-id 10260284 \
  --snapshot s9-s10-practice.json --validate
```

直接執行 `player` 時，每次重新讀取兩屆的公開圖池與成績投影。`practice-snapshot` 保存重跑所需的公開欄位及來源版本。要試算節奏間距變化率及持續密度，可在擷取時指定 `--osu-dir DIR`，沿用[第一階段的 checksum 核對流程](README.md#固定資料重跑)。已擷取的快照包含當時的發布狀態。

## 比較方式

- 先確認單圖成績出自已覆蓋的公開場次，且 BID 和欄位吻合該場發布的圖池。以實際完整 MOD 驗證譜面設定，不用欄位名稱推測選手使用的 MOD。公式使用原始分數，沿用網站至少 2,000 分的出賽門檻。無法確認圖池、MOD、數值快照或版本、技術裁決場次、重複成績與同場同條件樣本過少，會列出排除原因。
- 比較基準是同屆、同場、同一局、同譜面、同完整 MOD（包含 NF）和同計分方式的其他選手原始分數中位數。至少需要三位可比選手。個人分數除以該基準，1.00 表示等於同組中位數。NF 保留在比分的比對條件中，譜面特徵沿用第一階段的固定設定。[osu! NF 說明](https://osu.ppy.sh/wiki/en/Gameplay/Game_modifier/No_Fail)
- 在每種 MOD 內，從至少 8 張有該特徵的不同公開譜面估計第 60 百分位，將需求較高的譜面和其餘譜面分組。可評估 BPM、長度、AR、OD、CS、可用的 aim／speed，以及通過檔案核對的兩個代理指標。每個 BID 先取自己多局相對分數的中位數，分組時每張譜面各算一次。兩組各需有至少 4 次單圖出賽、3 張不同譜面、2 個不同場次。兩組中位數相差至少 0.08 才標示相對強項或練習方向。
- 從差距最大的三個可加強方向選擇已有實戰證據的種子。候選取相同 MOD、達到目標特徵門檻的公開譜面，排除該選手在兩屆公開成績中出現過的 BID。先找比種子低 0.15–0.75★ 的起步譜面，再找與種子相差至多 0.15★ 的相近難度。各區間依同一套 pgvector 特徵距離排序，缺少可用候選時顯示空值。結果包含種子對局、兩組樣本、特徵門檻、星數差與候選來源。
- 輸出分組的單圖出賽次數、不同譜面數、場次數，以及同組其他選手的出賽人次。相對分數反映該選手實際上場選到的譜面及同場其他選手。長度、速度、讀譜等需求可能同時變動。保存的官方難度快照按公開圖池的 BID／MOD 對接，歷史成績沒有保存實戰當時的譜面 checksum。

## 時間切分

`--validate` 以 2025-01-01 UTC 為界。技術門檻只從 S9 圖池擬合，待驗證的方向只由 S9 實戰決定。S10 用相同門檻和每局自己的同條件比較基準驗證，排除選手在 S9 已有公開成績的 BID。這是以現存譜面快照做的回顧性分析。

雙季範例有 S9 的 62 次單圖出賽和 S10 的 46 次留驗出賽。S9 的高 aim DT 相對較弱（6 局對 10 局，差距 −0.212），在 S10 再次出現（5 局對 10 局，差距 −0.335）。另有三個方向未重現，六個方向的 S10 樣本不足。結果用來檢查歷史模式是否延續。實際練習後的成效需要有練習前後的資料。[S9 樣本來源](https://oclr.org/tournaments/s9/statistics) · [S10 範例對局](https://oclr.org/tournaments/s10/matches/match-22)
